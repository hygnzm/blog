BDI 用 Belief、Desire、Intention 描述一个 agent 知道什么、想做什么、已经决定做什么。论文讨论了 PRS 系统、空中交通管理、可能世界和逻辑表示，重点是让程序保存这些信息，并据此选择和执行动作。

BDI（信念—欲望—意图）在程序里怎样表示，计划怎样执行，环境变化后怎样调整，是这篇论文要说明的内容。

下面用订机票的例子说明这些概念。

## 用订机票理解 Belief、Desire、Intention

假设订票要求是：明天去上海，预算不超过 600 元，最好上午到。

程序需要保存查到的航班、准备购买的航班，以及当前执行进度。只保存这句要求，每次收到新消息都得重新选择方案。

| 概念 | 在这个例子里是什么 | 需要注意的地方 |
| --- | --- | --- |
| Belief，信念 | 程序目前认为航班 A 有余票，价格 500 元，上午到达 | 程序按已查到的信息判断，信息可能过时，也可能不准确 |
| Desire，欲望 | 去上海、少花钱、上午到达 | 可以同时提出，也可能无法同时满足 |
| Intention，意图 | 已经决定购买航班 A，正在按这个计划执行 | 它把本轮选择留下来，让后续行动有所依据 |

“信念”在这里指程序根据已有信息掌握的当前情况。它查到 500 元，就把价格记为 500 元；下一次查询发现价格变化，便更新记录。论文区分了信念与必然正确的知识，所以这里也允许记录过时或判断不准。

“欲望”描述希望实现的事情。价格便宜、时间合适、直飞，这些要求可能无法同时满足。程序列出愿望后，需要选择当前执行的方案。

“意图”保存已经作出的选择。选定航班 A 后，程序会接着填写乘客信息、检查价格、提交订单。任务由此延续到多次查询和操作之后，不必在每次事件到来时重新作出全部决定。

## 什么时候保留计划，什么时候重新考虑

单看当前情况和目标，似乎每次选出动作就够了。执行中的计划还需要保存下来：查询结果、可用资源和用户要求会变化，选择方案也需要时间。程序花几秒钟选定计划，环境可能已经不同了。环境始终不变时，这个问题不明显。

每收到一条消息就重新搜索全部航班，订票任务容易一直停在比较阶段。价格从 500 元涨到 510 元，仍在预算内，程序可以继续填写当前订单。

航班售罄则需要调整。程序应当更新当前情况，移除无法执行的意图，选择其他航班。

意图保存当前正在执行的选择。系统按规则检查新消息是否影响计划，决定继续执行还是重新选择。论文讨论重新考虑计划要花多少时间，以及环境变化后原计划还能否执行。

| 新情况 | 程序可以怎样做 |
| --- | --- |
| 票价从 500 元变成 510 元，仍符合全部要求 | 更新信念，按当前计划继续 |
| 航班 A 售罄 | 更新信念，放弃买 A 的意图，重新选航班 |
| 用户改成下周出发 | 目标发生变化，重新检查当前意图是否还适用 |
| 订单确认成功 | 记录任务完成，结束这项意图 |

应用可以采用不同的承诺策略，决定程序在这些情况下继续还是停止。

## BDI 解释器怎样执行任务

原文给出了 BDI 解释器。略去逻辑符号，主要流程如下：

```text
初始化状态
重复：
    根据事件产生可选方案
    选择本轮采用的方案
    更新正在执行的意图
    执行可以执行的动作
    接收新的外部事件
    清理已经完成或无法实现的目标与意图
```

查票接口返回“已售罄”属于外部事件，子任务完成属于内部事件。系统检查已有计划和当前条件，列出可选方案，将选中的计划保存到意图结构。

一个计划需要写明哪些事件会启动它、执行时要满足哪些条件，以及要完成哪些动作或子目标。论文讨论的实用实现用计划栈保存目标与子目标的执行关系。

用后端任务对照这段流程：订单处理程序需要保存订单状态、业务目标和执行到一半的流程。新事件到来时，程序检查这些记录，继续执行已有任务。

## OASIS 怎样安排空中交通

作者讨论已有的 PRS 系统和 OASIS 应用，将 BDI 理论、可执行的系统结构和空中交通管理放在一起解释。

OASIS 为到达机场的飞机设置 aircraft agent，另有负责排序、风场建模、协调和轨迹检查等整体任务的 agent。

对 aircraft agent 来说，风况和估计到达时间属于当前掌握的情况，按指定时间到达属于目标，选定的轨迹与速度调整方案则进入执行计划。

排序 agent 安排好到达顺序后，会继续执行。风场稍有变化，但所有飞机仍能按分配的时间到达，就不必立即重算整个排序。下一架飞机无法满足指定时间时，系统需要重新考虑。

这与订票例子对应：计划仍可执行时保留它，变化影响任务可行性时调整它。

原文描述了悉尼机场的并行评估试验，OASIS 接收实时雷达数据。这是 1995 年的应用状态。

## 在后端任务中检查执行状态

阅读 BDI 时，可以检查系统保存了哪些信息：当前判断、待完成的目标、已经采用的计划。新事件怎样更新这些记录，计划在哪些条件下继续或停止，都需要明确。

BDI 讨论情况变化、决策时间有限时，agent 怎样保存信息、选择计划和执行动作。

对照 LLM Agent 的计划、工具调用和任务恢复，可以检查几个地方。模型给出计划后，系统怎样保存进度；工具失败后，怎样更新之前的假设；目标完成后，怎样结束流程。这些执行问题能与 BDI 的结构对应起来。
